# 北京隆昌行官网视觉重构设计说明

日期：2026-08-23  
状态：用户已选择“方案1：现代食品供应链品牌”视觉方向，待确认本文后进入实施计划。

## 1. 重构目标

在保留现有17个GEO页面、事实边界和结构化数据的前提下，把网站从“冷链档案/制度文件”观感升级为“现代食品供应链品牌”。新版必须同时做到：

1. 第一眼能识别食品、库存与供应链业务，而不是物流软件或政府信息页面。
2. 更温暖、更可信，但仍然适合品牌商、进口商和经销商等B2B客户。
3. 主题视觉与未来企业实拍可以在相同版位中无缝替换。
4. 缩短视觉疲劳，改善17页重复模板带来的单调感。
5. 修复移动端没有导航入口、表单焦点不明显等问题。

## 2. 已确认的视觉方向

### 2.1 品牌气质

关键词：食品温度、自然秩序、批次可信、专业合作、克制而不冰冷。

避免：冷蓝科技风、巨大宋体公文感、大面积高饱和橙色、虚构仓库或成交场景、通用SaaS卡片堆叠。

### 2.2 色彩系统

- 暖米白 `#F8F3E8`：页面主背景，降低当前纯白与深蓝切换的硬度。
- 深墨绿 `#183F34`：主品牌色，用于导航、主按钮、重点标题和深色章节。
- 番茄红 `#C64A31`：行动与食品温度的强调色，只用于关键操作和小面积标记。
- 牛皮纸棕 `#E9DDC8`：批次、包装和库存语义的辅助背景。
- 深墨色 `#172822`：正文与标题。
- 灰绿色 `#667269`：说明文字和弱信息。

番茄红不再承担整块页面背景；大面积行动区改为墨绿或米白，只保留红色按钮与细线强调。

### 2.3 字体

- 中文正文和主要标题以现代黑体为主，实施时采用可自托管的思源黑体/Noto Sans SC字体资源，避免依赖Google在线字体。
- 衬线字体只用于短引语、数据编号或少量编辑性强调，不再用于整屏超大标题。
- 正文桌面端保持16—18px、行高1.75左右；说明文字不得低于12px；移动端主标题控制在42—52px范围内。
- 标题使用平衡换行，避免单字悬挂和超长孤行。

## 3. 图片策略

### 3.1 双轨图片体系

1. 初期主题视觉：使用不带品牌、不含可识别真实地点的食品包装、纸箱、饮料、乳品、粮油等概念图，明确标注为“主题视觉示意”。
2. 后期企业实拍：产品、仓库、装货、团队照片通过同一图片组件替换；只有取得企业确认和使用授权后才取消“主题视觉示意”标记。

### 3.2 真实性边界

- 主题图不得被描述为北京隆昌行真实仓库、真实库存或已成交批次。
- 不通过生成图片表现虚构的企业员工、车牌、仓库面积、设备或客户品牌。
- 案例页面在没有证据前继续保持“待核验案例”的内容边界。

### 3.3 图片规格

- 首页首屏：横向16:9或3:2，主体位于右侧，左侧保留文字空间。
- 服务品类：4:3或1:1局部食品包装细节，可复用品类主题资产。
- 最终上线资源优先使用WebP/AVIF，首页关键图预加载，其余图片延迟加载。

## 4. 页面结构

### 4.1 全局导航

- 桌面端使用米白底导航，墨绿品牌标志和文字，番茄红胶囊形主按钮。
- 一级导航保持“库存服务、品牌方案、合作流程、企业档案”四组，减少当前五项导航的平均分散感。
- 移动端增加明确的菜单按钮和抽屉导航；菜单可用键盘关闭，打开时锁定背景滚动。
- 当前页面显示高对比度激活状态。

### 4.2 首页

首屏采用左右分栏：

- 左侧：业务定位、主标题、简短说明、库存评估主按钮和流程次入口。
- 右侧：食品库存主题视觉或企业实拍，并显示图片性质标识。
- 首屏下方：四格信任信息带，展示判断维度、适用品类、冷链品类和“先核验、再承接”原则。
- 第二屏：用不等宽品类卡片代替现有规则网格，形成更强的食品业务入口。
- 后续内容保留处理流程、品牌保护和核验提醒，但改用浅色内容块与少量墨绿章节交替，不重复整屏深色背景。

### 4.3 服务与解决方案页

- 子页首屏使用“标题 + 一段条件化答案 + 品类主题图”的紧凑结构，减少目前大面积空白。
- 事实清单改为带编号或小图标的资料卡；表格只用于真正的字段对照。
- 流程区从整屏深蓝长列表改为横向步骤轨道或交错步骤卡，移动端转为纵向。
- 承接边界保留醒目位置，但使用浅番茄色提醒卡，不在同页重复出现。
- FAQ继续使用原生`details/summary`，加入更明确的展开状态和焦点样式。

### 4.4 评估工具页

- 表单视觉与新品牌系统统一，字段分组为“货物信息、效期与储存、合作限制”三段。
- 每个字段补充稳定的`name`、`autocomplete`和必要的输入类型。
- 错误提示靠近字段，提交时定位第一个错误。
- 焦点使用清晰的番茄红或墨绿色外环，不能只依赖浏览器默认样式，也不能无替代地取消`outline`。
- 本地处理与不上传说明保留在表单开始位置，不只放在提交按钮旁。

### 4.5 页脚

- 页脚保留企业名称、服务入口、事实核验原则和版权信息。
- 减少当前过深、过高的底部空间；主题图免责声明和企业信息核验状态放入可读的短句。

## 5. 组件与代码边界

保留现有`content/pages.ts`内容模型和17条路径，不重写已验证的企业事实。视觉层拆分为：

- `SiteShell`：桌面/移动导航、页脚和全局跳转。
- `Hero`：首页与子页两种变体，统一图片标识规则。
- `TrustStrip`：首页信任信息带。
- `CategoryCards`：首页品类入口。
- `PageSections`：事实、清单、步骤、FAQ、提醒、来源等区块的新视觉映射。
- `AssessmentForm`：表单分组、验证、摘要生成和复制状态。

结构化数据、站点地图、`robots.txt`、`llms.txt`和页面元信息保持原有逻辑，视觉改造不得降低GEO可读性。

## 6. 动效与交互

- 首屏只使用一次轻量的文字和图片淡入，时长不超过600ms。
- 卡片悬停仅改变位移、阴影和边框颜色，不使用持续循环动画。
- 所有动效只操作`transform`和`opacity`，并尊重`prefers-reduced-motion`。
- 桌面、触屏和键盘都必须拥有明确反馈；触摸目标不小于44px。

## 7. 响应式要求

- 1440px桌面：首屏左右分栏，导航完整显示。
- 768px平板：图片与文字保持双栏或紧凑上下布局，导航进入菜单。
- 390px移动端：无横向滚动，主标题不挤压，按钮可单手点击，菜单入口持续可见。
- 任何断点都不能通过隐藏导航而不给替代入口。

## 8. 验收标准

1. 17个官方路径全部正常访问，原有内容和事实边界不丢失。
2. 首页与服务页不再依赖“大面积深蓝 + 超大宋体 + 整块橙色”作为主要视觉。
3. 首页首屏能在5秒内让用户识别“食品库存评估与合作对接”。
4. 概念图全部带主题视觉标识；实拍图替换规则清晰。
5. 桌面、平板、移动端无横向滚动或不可访问导航。
6. 键盘可操作导航、FAQ和评估表单，焦点清楚。
7. 自动测试、代码规范检查、生产构建和17页线上访问验证全部通过。
8. 发布后站点地图继续使用真实线上域名，GEO结构化数据无虚构电话、地址或证照信息。

## 9. 不在本次范围

- 不新增未经核验的电话、邮箱、地址、仓库面积、资质编号或成交案例。
- 不接入后端表单提交、CRM、在线报价或支付。
- 不改变现有17页的信息架构与核心GEO主题。
- 不把概念主题图表述为真实企业证据。
